# Security patch review — 2026-11-09

This review covers the WaldJS workspace packages, rendering and build boundaries, and the root pnpm dependency graph. It is a source review with regression tests and dependency advisory checks, not a penetration test or a guarantee that all vulnerabilities have been found. The independently locked Astro and Eleventy comparison sites under `benchmarks/` are outside this dependency audit.

## Code findings and fixes

| Severity | Finding | Trigger and impact | Fix |
| --- | --- | --- | --- |
| High | HTML injection in canopy props | An untrusted prop containing an apostrophe could break out of the single-quoted `data-props` attribute and inject executable HTML into a generated page. | Serialize props through the existing HTML-escaping template renderer. Preserve trusted component markup and JSON round trips. |
| High | Executable Markdown frontmatter | A content file beginning with `---js` or `---javascript` selected gray-matter's eval-based engine, allowing content authors to execute code with the build process's privileges. | Reject the JavaScript engine, including its aliases. YAML and JSON remain supported. This restriction concerns Markdown collections; `.wald` frontmatter remains application code. |
| Medium | Build output path traversal | A `getStaticPaths()` parameter derived from external content could contain enough `../` segments to write `index.html` outside the build directory. | Resolve the destination and verify containment before writing. Handle both separator styles and treat replacement metacharacters literally. |
| Medium | Image attribute injection | Image `src` or generated `srcset` values containing quotes could introduce extra attributes in rendered HTML. | Escape URLs in production and development image markup. |

Severity depends on attacker control over props, content, or route parameters. Static sites need rebuilding and redeploying to receive the rendering fixes. Path containment assumes the build directory is controlled by the project; it does not defend against an attacker who can replace filesystem paths with symlinks during a build.

## Dependency changes

- CLI: Vite 5 → 6.4.6, esbuild 0.21 → 0.25.12, sharp 0.33 → 0.35.5.
- Tests: Vitest 2 → 4.1.12 and Happy DOM 15 → 21.0.4.
- Benchmarks: Lighthouse 12 → 13.6.0, removing vulnerable older browser tooling and telemetry dependencies.
- Refresh compatible transitive packages in `pnpm-lock.yaml`, including YAML and CSS parsers.

The initial root audit reported 45 advisories: 4 critical, 19 high, 21 moderate, and 1 low. After updates the root `pnpm audit` reports zero advisories. This reports known dependency advisories, not independent proof that the dependencies are secure.

The CLI now declares Node.js >=20.9.0 to match sharp's runtime requirement. CI uses Node.js 22. Projects supplying custom Vite `resolve.conditions` or `ssr.resolve.conditions` should review the [Vite 6 migration guide](https://v6.vite.dev/guide/migration). See also the [sharp advisory](https://github.com/advisories/GHSA-wq5f-xc86-pv6w) and [Vitest mock registration advisory](https://github.com/advisories/GHSA-qxg6-89mg-rqv8).

## Verification

Regression tests cover canopy HTML injection and JSON recovery for all hydration strategies, image URL injection, route containment with Unix and Windows separators, and rejection of JavaScript frontmatter without executing its payload. Existing integration tests exercise actual esbuild bundles and scaffolded projects. esbuild 0.28.2 was rejected after its browser-target transformation failed the actual canopy bundling test; the patched 0.25 series preserves the existing browser targets.

The security changeset was applied to release @waldjs/cli 0.14.1, @waldjs/compiler 0.5.1, @waldjs/content 0.3.1, and create-wald 0.1.20. Publishing follows the existing Changesets release workflow after merging.

Final checks passed: `pnpm build`, `pnpm test` (559 tests across seven packages), `pnpm audit` (zero advisories), `pnpm peers check`, `git diff --check`, and Changesets release-plan validation. The marketing site also built successfully with `WALD_SSR_BUNDLER=vite`. Lighthouse's updated module imported successfully; the full browser benchmark suite was not run.
